# 吾也乐队管理系统 · Band Hub

> 统一入口 · 模块独立 · 入口纯净 · 可复制 · 有护城河
> v1.8 · 2026-08-29 · 排练质量控制三层方案（合格线/冗余/清单）+ 复盘沉淀回路（沉淀清单→教训库）

---

## 1. 这是什么

吾也乐队的「中央控制台」。把所有运维工具整合到一个入口、一套结构里，按「信息生命周期」组织：

| 类型 | 核心特征 | 对应模块 |
|---|---|---|
| **资产** | 越攒越值钱，长期保留 | 曲库、乐队介绍、风控速查、演出手册、财务对账 |
| **流程** | 每周滚动，过期归档 | 通告 |
| **回路** | 把经验喂回系统 | 复盘评估 → 曲库/风控 |

## 4. 五步上手清单

| 步骤 | 做什么 | 怎么做 |
|---|---|---|
| **第 1 步** | 打开入口 | 双击 `index.html`，用浏览器打开 |
| **第 2 步** | 检查内容 | 依次点开卡片，确认曲库、通告、风控、手册、财务、复盘都能打开 |
| **第 3 步** | 发乐队群 | 把整个文件夹打包发群，或上传 GitHub Pages 后发链接 |
| **第 4 步** | 下次排练试用 | 发通告→通告速填器；排练后→更新曲库；演出前→风控速查+手册；演出后→复盘评估+财务对账 |

## 5. 日常操作手册（场景化）

### 5.1 发通告
1. 入口 → 通告中心 → **通告速填器**：选排练/演出 → 勾时间地点、到场人员 → 从曲库勾歌（可排序、指定演唱者）→ 有加急新歌就补一行
2. 点「生成通告」→ 检查文本 → 「复制」→ 粘贴发乐队群
3. 点「确认发布」本场编号自动 +1；重要场次再把速填器生成的关键字段补进 `通告.xlsx` 台账
> 速填器管「快速创建+分发」，Excel 管「长期台账+模板」。曲库扩充后找 AI 更新速填器里的曲库数据即可让新歌可勾选。

### 5.2 演出前准备
1. 入口 → 演出风控速查 → 准备清单 → 勾选本场场景+到场人员 → 逐项检查 → 复制就绪汇总发群
2. 入口 → 演出风控速查 → 团队版（单场）/ 长期活动版（驻演）→ 逐项勾选
3. 入口 → 演出手册+串词 → 填歌单编排、分工、串词关键词

### 5.3 演出后复盘
1. 入口 → 复盘评估系统 → 点数字打分 → **第6节把踩坑逐条登记成沉淀清单**（类型+对策）→ 自动生成报告
2. 复制报告发乐队群存底；点「打印/存PDF」→ 另存为 PDF → 按 `YYYY-MM-DD_场地_类型.pdf` 命名
3. 把 PDF 上传到 `review/archive/`，在归档索引加一行
4. 点「复制沉淀清单」→ 打开**教训库**粘贴导入——跨场累积，统计条哪个类型最多就是系统性短板
5. 根据曲库优化规则（≥20王牌/15-19灵活/≤14特定）更新曲库状态；曲目型教训去对照排练合格线，设备/流程型去补提醒清单

### 5.3.1 排练合格线（v1.8，全队统一标准）
- **上台资格**：连续 2 遍无结构性失误（进错段/合崩/忘词超一词/solo错段），隔周复验仍干净才算能上台
- **衔接点单过**：转调处、器乐交接、安静后齐炸、开头4拍与收拍——每首单独过
- **降级方案**：solo 错了不救直接跳下一段；合崩看鼓手拉回——排练时练"错了怎么办"比多排 5 遍有用
- **曲目池超配**：演 12 备 3，备选从复盘 15 分以上（灵活档）挑
- 详见演出手册「排练合格线」章节

### 5.4 更新曲库
入口 → 曲库管理 → 打开 `曲库.xlsx` → 在对应歌单 sheet 新增或更新

> 曲库变动后想让**通告速填器**同步可选新歌：把改过的曲库文件发给 AI，说"用最新曲库更新速填器的 DATA 块"，AI 会重新提取去重并更新页面（曲名写全，别截断——速填器按曲名去重合并）。

### 5.5 财务对账
1. 入口 → 财务对账 → 勾选出勤成员、填金额 → 保存本场（顶部自动汇总）
2. 攒够一批后点「导出 Excel」→ 下载到电脑，用 WPS 打开另存为 .xlsx（权威源）
3. 上传 GitHub 云端备份（`modules/finance/财务对账.xlsx`）
4. 分账规则：净结余（应收-成本）按出勤人头均分；基金平时不抽成，需要时全员凑

## 7. 部署与更新（不用命令行）

**首次上线**：跟着《部署指南.html》操作——建仓库 → 网页拖拽上传 → 开通 Pages → 发群链接，全程点鼠标，约 10 分钟。

**日常更新**（两种，都只要点鼠标）：
- **改 Excel**（曲库/通告）：电脑上改好 → 仓库页面 `Add file → Upload files` → 拖入同名文件（自动覆盖）→ `Commit changes` → 几分钟后全队看到新版
- **改网页文字**（介绍页联系方式等）：仓库里点开文件 → 铅笔图标 ✏️ → 直接改 → `Commit changes`

**进阶**（会用命令行的人可选）：

```bash
git add -A
git commit -m "更新说明：如 2026-08-20 添加商演通告"
git push
```

每次 push 即自动备份+发布，改坏了随时回滚到历史版本。
