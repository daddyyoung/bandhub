# 吾也乐队管理系统 · Band Hub

> 统一入口 · 模块独立 · 入口纯净 · 可复制 · 有护城河
> v1.1 · 2026-08-18 · 全部真实文件已整合

---

## 1. 这是什么

吾也乐队的「中央控制台」。把所有运维工具整合到一个入口、一套结构里，按「信息生命周期」组织：

| 类型 | 核心特征 | 对应模块 |
|---|---|---|
| **资产** | 越攒越值钱，长期保留 | 曲库、乐队介绍、风控速查、演出手册 |
| **流程** | 每周滚动，过期归档 | 通告 |
| **回路** | 把经验喂回系统 | 复盘评估 → 曲库/风控 |

## 4. 五步上手清单

| 步骤 | 做什么 | 怎么做 |
|---|---|---|
| **第 1 步** | 打开入口 | 双击 `index.html`，用浏览器打开 |
| **第 2 步** | 检查内容 | 依次点开卡片，确认曲库、通告、风控、手册、复盘都能打开 |
| **第 3 步** | 填介绍页联系方式 | 打开 `modules/intro/index.html`，替换微信号和电话 |
| **第 4 步** | 发乐队群 | 把整个文件夹打包发群，或上传 GitHub Pages 后发链接 |
| **第 5 步** | 下次排练试用 | 发通告→通告中心；排练后→更新曲库；演出前→风控速查+手册；演出后→复盘评估 |

## 5. 日常操作手册（场景化）

### 5.1 发通告
入口 → 通告中心 → 打开 `通告.xlsx` → 复制模板sheet → 填写 → 在汇总表加一行 → 复制关键字段发群

### 5.2 演出前准备
1. 入口 → 演出风控速查 → 团队版（单场）或长期活动版（驻演）→ 逐项勾选
2. 入口 → 演出手册+串词 → 填歌单编排、分工、串词关键词

### 5.3 演出后复盘
1. 入口 → 复盘评估系统 → 填观众打分、每首歌评分、自检清单
2. 根据曲库优化规则（≥20王牌/15-19灵活/≤14特定）更新曲库状态
3. 把踩坑补进风控速查表
4. 把亮点反哺乐队介绍页
5. 归档：拍照存入 review/archive/，在归档索引加一行

### 5.4 更新曲库
入口 → 曲库管理 → 打开 `曲库.xlsx` → 在对应歌单sheet新增或更新

## 7. 部署与更新（不用命令行）

**首次上线**：跟着《部署指南.html》操作——建仓库 → 网页拖拽上传 → 开通 Pages → 发群链接，全程点鼠标，约 10 分钟。

**日常更新**（两种，都只要点鼠标）：
- **改 Excel**（曲库/通告）：电脑上改好 → 仓库页面 `Add file → Upload files` → 拖入同名文件（自动覆盖）→ `Commit changes` → 几分钟后全队看到新版
- **改网页文字**（介绍页联系方式等）：仓库里点开文件 → 铅笔图标 ✏️ → 直接改 → `Commit changes`

**进阶**（会用命令行的人可选）：

```bash
git add -A
git commit -m "更新说明：如 2026-08-20 添加商演通告"
git push
```

每次 push 即自动备份+发布，改坏了随时回滚到历史版本。
